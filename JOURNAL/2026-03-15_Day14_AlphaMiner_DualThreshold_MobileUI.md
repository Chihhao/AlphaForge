## 學習重點 (The "Why")

### 1. 一個策略，為什麼需要兩套賠率比？

原本每個策略只有一個門檻（tlo）和一個賠率比。新設計加入了高門檻（thi）版本。

| 指標 | 低門檻（tlo）| 高門檻（thi）|
|------|------------|------------|
| 5日/10日 | >3% 漲 / <-3% 跌 | >5% 漲 / <-5% 跌 |
| 30日 | >5% 漲 / <-5% 跌 | >10% 漲 / <-10% 跌 |

**為什麼有意義**：低門檻衡量「一般行情的方向性」，高門檻衡量「強勢行情的選股能力」。一個好策略在高門檻下賠率比依然 > 1，代表它不只是「剛好上漲」，而是真的能選出強勢股。

**後端新增的三個欄位**：
```python
loss_rate_outsample_hi  # Top20% 中 < -thi 的比例
odds_ratio_hi           # win_rate_hi / loss_rate_hi
market_loss_rate_hi     # 全市場 < -thi 的基準比例
```

觸發重訓後，高門檻欄位從預設值 0.0 變成實際數字，前端的展開卡片才能正確顯示。這提醒了一件事：**schema 加欄位後，一定要觸發重訓，才能看到真實數值**。預設值 0.0 不會報錯，但會讓 UI 顯示錯誤資訊。

### 2. 手機版 UI：使用者最想看什麼？

這次手機版設計歷經多次迭代，根本問題是：**有限的螢幕空間要給哪些資訊？**

迭代過程：
1. 第一版：四格 2×2（勝率/踩雷率各×2）→ 卡片太高，頁面很長
2. 第二版：四格 1×4 橫向排列 → 字太小，看不清楚
3. 第三版：左低門檻/右高門檻兩欄，各含賠率比/勝率/踩雷 → 最終採用

**使用者最關心的優先序**：
1. **賠率比有沒有 > 1**（期望值正負）
2. **勝率多高**（方向性）
3. **踩雷率多低**（下行風險）

顏色語意（台股紅漲綠跌）：
- 賠率比 ≥ 1.2 → 琥珀色（強）；≥ 1.0 → 白色；< 1.0 → 紅色
- 勝率/踩雷率優於市場基準 → 綠色；否則 → 紅色

### 3. DetailPanel 的策略子標題：解釋「KD-K + 營收YoY 是什麼」

展開卡片後，標題只有「KD-K + 營收YoY」，使用者不知道這是什麼意思。加入子標題後：

```
KD-K + 營收YoY
「KD-K 動能 (-0.01)」與「年營收成長 (+0.34)」的多因子策略
```

這裡有個有趣的發現：KD-K 的係數是 -0.01（幾乎沒有貢獻），年營收成長係數是 +0.34（主要驅動力）。這說明這個「雙因子策略」實際上幾乎是單因子策略（營收YoY），KD-K 的存在幾乎沒有增量信息。

**教訓**：邏輯迴歸會自動壓低無用因子的係數，顯示係數讓使用者能直覺判斷「這個策略真正依賴哪個因子」。

### 4. 63 組因子組合是「挖掘」還是「驗證」？

使用者直接提問：「人工設定好 63 種的話，這樣不就不是 miner 的嗎？」

這是個很好的哲學問題。嚴格說來，Alpha Miner 目前是「人工設計組合 + 系統學出權重」，不是純粹的自動挖掘。

真正的自動挖掘（FDR + 窮舉）要解決的問題：
- 24 個因子取 2 = 276 組；取 3 = 2,024 組
- 窮舉後需要 FDR（Benjamini-Hochberg）控制假發現率
- 但大多數組合沒有投資邏輯，即使統計顯著也可能是噪音

**結論**：瓶頸不在「搜索廣度」，而在「因子品質」。先用 Phase 6 擴充有意義的新因子（外資持股比例、產業相對強度），再考慮更系統的搜索方式。

## 開發成果

### 後端：雙門檻賠率比

**新增欄位**（`schemas/alpha_miner.py`）：
```python
loss_rate_outsample_hi: float = 0.0  # Top20% 中 < -threshold_high 的比例
odds_ratio_hi: float = 1.0           # win_rate_hi / loss_rate_hi
market_loss_rate_hi: float = 0.0     # 全市場 < -threshold_high 的基準
```

**計算邏輯**（`services/alpha_miner_service.py`）：
```python
loss_rate_outsample_hi = float((top_returns < -thr_hi).mean())
odds_ratio_hi = round(win_rate_outsample_hi / max(loss_rate_outsample_hi, 0.001), 2)
market_loss_rate_hi = float((all_returns < -thr_hi).mean())
```

## 遇到的問題與解法

### 展開前顯示高門檻踩雷 0%，展開後卻有實際數字
**原因**：高門檻踩雷欄位是這次才新增的，模型尚未重訓，預設值 0.0。展開後顯示 29.3% 是舊訓練結果中已計算的資料，兩者資料來源不一致。
**解法**：觸發 `POST /alpha-miner/train` 重訓後，所有欄位同步更新。

### deploy.sh 路徑不存在
**原因**：電腦改名或 Synology Drive 重新設定後，NAS 同步資料夾路徑改變。
**解法**：SSH 進 NAS 執行 `find /volume1/homes/chihhaolai -name 'AlphaForge' -type d` 找到正確路徑。
