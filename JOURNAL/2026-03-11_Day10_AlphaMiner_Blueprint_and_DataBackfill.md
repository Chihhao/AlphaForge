## 🧠 今日學習重點 (The "Why")

### 1. 從「工具箱」到「智慧投顧引擎」
- **核心轉變**：AlphaForge 的終極目標不是讓 user 自己組合公式（門檻太高），而是由系統**自動從歷史數據中挖掘勝率最高的策略公式**，直接呈現量化的「明日上漲機率」與「兩週後勝率」。
- **產品命名**：將此功能定位為「**Alpha Miner（策略金鑰挖掘機）**」，未來會是 AlphaForge 的核心競爭力。

### 2. 「明日勝率」何時有意義？
- **短線策略**：當 user 的策略是技術面驅動（如 KD 金叉、量價突破）時，預估明日勝率是核心指標。
- **基本面策略**：像「AF 精選」這種長線策略，明日勝率接近擲硬幣（~50%），應改為預估兩週或一個月的勝率。
- **結論**：系統需同時支援多個時間維度的勝率預估，取決於策略性質。

### 3. 資料一致性的重要性
- **問題**：yfinance 的「調整後價格」與 TWSE/TPEx 官方的「原始價格」如果混用，會在除權息日產生假跳空，導致所有技術指標失真。
- **決策**：選擇 FinMind 作為歷史回補來源，因其數據來自 TWSE/TPEx 官方，與現有 `MarketDataCrawler` 100% 一致。
- **教訓**：**資料正確比速度更重要**。即使 FinMind 有每小時 600 次的速率限制，也值得等待。

## 🏗️ 開發與維運成果

### ✅ Alpha Miner 產品藍圖 [NEW]
- **文件**：`docs/Alpha_Miner_Blueprint.md`
- **內容**：定義了 6 個 User Stories（初階/進階/系統維度）、4 個核心技術指標（明日機率、兩週勝率、期望報酬、Alpha 分數）、四階段 Roadmap。

### ✅ 全市場歷史價格回補 [NEW]
- **腳本**：`scripts/backfill_prices.py`
- **技術**：使用 FinMind REST API 批量下載 TWSE/TPEx 官方原始價格數據
- **功能特性**：
  - 去重複（已有的日期自動跳過）
  - 速率限制自動等待重試（每次等 10 分鐘，最多 3 次）
  - 內建 log 檔輸出（解決管線 buffering 問題）
  - 支援乾跑模式 (`--dry-run`)

### ✅ 回補成果

| 指標 | 回補前 | 回補後 |
|:---|:---|:---|
| 總紀錄數 | 112,647 筆 | **1,410,085 筆** (⬆️ 12.5x) |
| < 30 天的股票 | 850 支 | 6 支 |
| 有 2-3 年完整資料的 | 0 支 | **1,875 支 (96%)** |
| 失敗股票 | — | 6 支（可能已下市） |

### ✅ 原子指標特徵庫實作 [COMPLETE]
- **模型**：`StockFeature` (包含 RSI, KD, MACD, MA, Bias, Bollinger 等 25 個指標欄位)
- **服務層**：`FeatureService` (支援單日 snaphost 與批量歷史回補)
- **排程器**：在 `scheduler.py` 掛載每日 17:05 自動計算當日特徵

### ✅ NAS 部署與遠端執行 (Remote Execution) [COMPLETE]
- **GitHub 檔案限制處理**：`test.db` 超過 100MB 限制，已從 Git 追蹤中移除並設定 `.gitignore`。
- **資料庫同步**：利用 Synology Drive 成功將 194MB 的歷史資料庫同步至 NAS。
- **遠端運作策略**：
  - **原則**：確定「NAS 為唯一數據真相」。開發在本地，數據運算在 NAS。
  - **執行**：在筆電下達 SSH 指令，驅動 NAS 內部的 Docker 程序進行大數據運算。
  - **具體動作**：已啟動全市場 3 年份的「特徵回補 (Feature Backfill)」，預計產生約 140 萬筆特徵快照。
