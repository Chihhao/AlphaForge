## 🧠 今日學習重點 (The "Why")

### 1. 籌碼面（三大法人）為什麼重要？
- **外資（Foreign Investor）**：掌握大量資金，長期持倉，買超代表對基本面有信心
- **投信（Investment Trust）**：國內法人，季末有作帳壓力，短中期買超具有跡象意義
- **融資（Margin）**：散戶追漲的指標，融資餘額持續增加代表散戶過度樂觀，反而是危險訊號
- **今日結論**：「投信5日累積買超」直接登上 Alpha Miner 第一名（IC=0.089），超越 RSI+MACD 等技術指標——**籌碼面是比技術面更領先的訊號**。

### 2. 為什麼有資料還是算不出來？— 合併欄位的陷阱
- **問題**：回補 86 萬筆籌碼資料後，stock_features 裡的籌碼欄位仍然 100% 是 NULL。
- **根本原因**：`backfill` 函數先對整個 DataFrame 預先初始化籌碼欄位為 `None`，再執行 `merge`。Pandas 遇到兩個 DataFrame 有同名欄位時，自動改名為 `_x`/`_y`，導致程式讀到的永遠是原本的 `_x`（全 None）。
- **修正**：merge 之前先 `drop` 掉預初始化的欄位，讓 merge 後只有一個名字。
- **教訓**：加資料後一定要先驗證「欄位有沒有值」，再去跑模型。不然模型跑出來的結果和沒加資料一模一樣，卻不知道哪裡出了問題。

### 3. 快取存在記憶體 vs 存在資料庫的差異
- **原本設計**：訓練結果存在 Python class 變數（記憶體）
  - 同一天同一個 process → 秒回 ✅
  - **後端重啟 → 快取消失，重新訓練 2~3 分鐘** ❌
- **今日改進**：訓練完成後序列化為 JSON 存入 `alpha_miner_snapshot` 表
  - 後端重啟 → 從 DB 讀快照，秒回 ✅
  - 隔天第一次請求 → 先回傳昨日快照，同時背景重訓今日模型 ✅
- **原則**：凡是計算昂貴、使用者體驗時間敏感的資料，都要考慮持久化。

### 4. IC（Information Coefficient）是什麼？
- **定義**：模型預測分數排名與股票實際報酬排名的 Spearman 相關係數
- **直覺理解**：模型排出的股票順序，跟實際漲跌的順序，有多少一致性
- **業界標準**：
  - < 0.02：沒有預測力
  - 0.02~0.05：一般水準
  - **0.05~0.10：良好，專業基金常見水準**（我們的最強因子 IC=0.089 落在這裡）
  - > 0.10：要懷疑過擬合

### 5. 「送分題」的本質探討
- **使用者期待**：等到某個策略勝率跳到 70%，那就是買進時機
- **現實問題一**：歷史勝率是固定的統計值，不會因為今天市場狀況而突然跳高
- **現實問題二**：邏輯迴歸輸出機率受訓練資料噪音壓縮，IC=0.089 對應的個別股票預測機率約在 0.45~0.60，極少突破 0.65
- **根本原因**：任何用公開資料的因子，都有大量人同時在看，市場會快速消化這個訊號，讓它變得不那麼準
- **正確理解**：Alpha Miner 的價值是「**縮小範圍**」，從 1800 支篩到少數高分標的，而不是找到「保證漲」的股票

## 🐛 今日修復的 Bug

### Pandas merge 欄位衝突（_x/_y）
```
問題：
  backfill_df[chip_cols] = None  # 先初始化為 None
  day_df.merge(day_chip, on='stock_id')  # 產生 foreign_net_buy_x / _y
  row.get('foreign_net_buy')  # 拿到 _x（None）

修正：
  day_df.drop(columns=chip_cols)  # merge 前先移除
  day_df.merge(day_chip, on='stock_id')  # 只有一個 foreign_net_buy
```

### chip_by_date 窗口資料不足
```
問題：backfill 對每個日期只傳當天一筆資料給 _build_chip_features，
      導致 5日累積無法計算（只有 1 筆）

修正：傳入完整的 chip_all（包含前後所有日期），讓函數自行取 5 天窗口
```

## 💭 今日心得
> 「今天最大的收穫是兩件事：一個技術上的，一個認知上的。
>
> 技術上，花了大半天在除錯籌碼欄位為什麼全是 NULL。最後發現是 Pandas merge 的一個細節——同名欄位會自動加 _x/_y 後綴，程式卻繼續用原始名稱讀取。這種 bug 最難找，因為程式不會報錯，只是靜靜地給你錯誤的答案。以後加入新欄位後，第一件事要先做資料驗證。
>
> 認知上，使用者問了一個很根本的問題：『勝率 48.9% 有什麼用？』這讓我重新思考 AlphaForge 的價值定位。量化模型的價值不在於找到『保證漲』的股票，而在於把 1800 支裡面相對有勝算的那幾支挑出來，讓使用者節省研究時間。這跟使用者想要的『送分題』之間有落差，需要在後續開發中持續溝通。」
